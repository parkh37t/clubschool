# 가상 사무실 ↔ 실제 오케스트레이터 연동 설계

> 목표: **사용자가 직접 지시 → 12 에이전트가 실제 산출물 생성 → 픽셀 오피스가 실시간 시각화.**
> 전제(정직하게): 배포된 브라우저 앱은 에이전트를 직접 실행할 수 없다. 에이전트는 `.claude/agents/*.md`의
> **Claude Code 서브에이전트**이며, 실제로 돌리는 "오케스트레이터"가 반드시 별도로 있어야 한다.

## 1. 3계층 구조

```
┌─────────────┐    지시(instruction)     ┌──────────────────────┐   상태(state)   ┌───────────────┐
│  ① 지시/제어 │ ───────────────────────▶ │  ② 실행 = 오케스트레이터 │ ─────────────▶ │  ③ 시각화      │
│  (사용자)    │                          │  Claude Code + 12 agents │   산출물(files) │  픽셀 오피스     │
│  채팅/입력창 │ ◀─────────────────────── │  + skills                │ ◀───────────── │  (VirtualOffice)│
└─────────────┘    산출물/결과            └──────────────────────┘                 └───────────────┘
```

- **② 실행 = 이미 존재한다.** 이 저장소의 `.claude/agents`(12인)+`.claude/skills`가 곧 오케스트레이터의 두뇌.
  이번 세션 내내 지시 → 실제 산출물(PPTX/DOCX/코드)이 나온 게 그 증거.
- **③ 시각화 = 이미 구현됨.** `VirtualOfficeView`가 `stateUrl`의 `office-state.json`을 2초 폴링해 반영(`applyOfficeState`).
- **빠진 것 = ①↔② 지시 입력과, ②→③ 상태/산출물 브리지.**

## 2. 연동 계약 (I/O)

오케스트레이터가 읽고/쓰는 3개 파일이 계약의 전부다.

| 파일 | 방향 | 내용 |
| --- | --- | --- |
| `_orchestrator/instruction.json` | 사용자→오케스트레이터 | 지시(제목·요구·마감·게이트 범위). `instruction.sample.md` 참조 |
| `office-state.json` (배포 `public/`) | 오케스트레이터→오피스 | 진행 상태(`OfficeState` 스키마). 오피스가 폴링 |
| `DELIVERABLES/<task>/` | 오케스트레이터→사용자 | 실제 산출물 파일 + `_index.md` 대장 |

`OfficeState` 스키마(= `components/VirtualOffice/officeSimulator.ts`의 export, 샘플 `office-state.sample.json`):
```ts
{ stage:0~5, phase:'meeting'|'returning'|'working'|'awaiting'|'done-all',
  progress:0~1, agents:{[id]:{state:'idle'|'working'|'waiting', task}}, artifact:{file,score} }
```
게이트 매핑: G1 영업/평가 · G2 기획 · G3 디자인 · G4 구현 · G5 검증/배포 · G6 그로스.

## 3. 경로 A — 세션 브리지 (오늘 바로 됨 · 인프라/키 불필요) ★권장 시작점

**오케스트레이터 = Claude Code / Cowork 세션.** 사람이 지시하면 세션이 게이트 파이프라인을 돌리며
산출물 + 상태를 쓴다. 지금 이 세션이 그대로 할 수 있다.

**흐름**
1. 사용자가 지시(채팅으로, 또는 `_orchestrator/instruction.json`에 기록).
2. 세션(오케스트레이터)이 게이트 순서로 담당 에이전트에게 위임:
   - G1 한도전/김영업 → G2 정우선/나기획 → G3 차도안/오색감 → G4 표준수/이풍뎅/백연동/구동민 → G5 고지표 → G6 홍보라.
3. 각 페이즈 전이마다 `public/office-state.json` 갱신(회의→작업→결재).
4. 산출물은 `DELIVERABLES/<task>/`에 실제 파일로 저장(pptx/docx/xlsx/코드 — 이미 하던 방식).
5. 게이트 통과 시 `artifact` 기록 → 오피스 산출물 패널에 적재.
6. 배포된 오피스(`stateUrl="/office-state.json"`)가 실시간 시각화.

**장점:** 인프라·API 키·서버 0. 오늘 즉시. 산출물이 진짜(에이전트가 생성).
**한계:** 세션이 떠 있어야 실행됨(사람 in-the-loop). 셀프서브 아님.

> 이 방식은 앞서 만든 **주간 회의(Google Calendar)** 나 **트리거/루틴**과 결합하면 반자동화 가능.

## 4. 경로 B — 스탠드얼론 제품 (셀프서브 · 백엔드+키+호스트 필요)

**오케스트레이터 = 서버가 Claude Agent SDK(또는 Claude Code 헤드리스)로 에이전트를 구동.**
사람 세션 없이, 앱의 제어 UI에서 지시 → 서버가 실행 → 상태/산출물 반환.

**구성**
```
[제어 UI(앱 내 지시 입력창)] ──POST /api/instruct──▶ [백엔드(Node/Express or Vercel Function)]
                                                        │  Claude Agent SDK + .claude/agents 로드
                                                        │  게이트 파이프라인 오케스트레이션
                                                        ├─▶ office-state.json (또는 SSE/WebSocket 스트림)
                                                        └─▶ DELIVERABLES/ (오브젝트 스토리지)
[픽셀 오피스] ◀──2초 폴링(또는 SSE)── office-state
```
- **필수 결정/자원:** ① 백엔드 호스트(Vercel Functions / 별도 Node 서버) ② **ANTHROPIC_API_KEY(서버 전용, 브라우저 노출 금지)** ③ 산출물 저장소(레포 커밋 / S3 / Supabase Storage) ④ 실행 방식(Agent SDK vs Claude Code 헤드리스).
- **보안:** API 키는 반드시 서버에서만. 지시 입력은 인증 뒤에(무단 실행·비용 폭주 방지). con-mgt의 JWT 인증을 재사용 가능.
- **실시간성:** 폴링(현행)로 충분하나, 부드럽게 하려면 SSE/WebSocket으로 상태 스트림.

**장점:** 셀프서브·상시가동·사람 세션 불필요.
**한계:** 백엔드 구축·키 관리·비용/레이트리밋·에러 처리 필요(2~4주 규모).

## 5. 권장

**A로 시작 → 검증 후 B로 승격.** 이유:
- A는 오늘 되고, 산출물이 진짜이며(에이전트 실동작), 리스크 0.
- "직접 지시 → 실제 산출물" 루프를 A로 먼저 돌려 가치를 확인한 뒤,
- 셀프서브가 필요해지면 같은 계약(§2) 위에 B(백엔드)를 얹는다 — 오피스·스키마는 그대로 재사용.

## 6. 결정 필요 (하나만 정하면 착수)
- **A 즉시:** 지시 입력 형식(채팅 vs `instruction.json`)만 정하면, 이 세션을 오케스트레이터로 삼아
  `office-state.json` 라이브 갱신 + 산출물 생성 루프를 바로 붙인다. 배포 오피스는 `stateUrl` 한 줄로 연결.
- **B 착수:** 백엔드 호스트(Vercel Functions 권장)·산출물 저장소·인증 범위를 정하면
  `/api/instruct` + 오케스트레이션 서버 + 앱 내 지시 UI 설계에 들어간다.

## 부록 · 착수 시 손댈 것
- (A) `public/office-state.json` 시드 + `ViewRenderer`에서 `<VirtualOfficeView stateUrl="/office-state.json" />`.
  오케스트레이터(세션)가 페이즈마다 이 파일 갱신 + `DELIVERABLES/<task>/` 기록.
- (B) 추가로 `api/instruct.ts`(서버), 상태 스트림, 앱 내 지시 입력/산출물 다운로드 UI.
- 공통 계약: `_orchestrator/instruction.sample.md` · `_orchestrator/office-state.sample.json`.
