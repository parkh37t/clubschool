# 컨버전스1팀 — 멀티 과제 운영 모델 (IBK 고정 금지)

> 원칙: **팀·스킬·도구·지식·캘린더는 과제와 무관하게 재사용**된다. 과제는 여러 개일 수 있고
> 어느 하나(IBK 등)에 고정하지 않는다. 새 과제는 아래 규약으로 추가한다.

## 1. 공유(과제 무관) vs 과제별
| 구분 | 위치 | 내용 |
| --- | --- | --- |
| **공유 — 팀** | `.claude/agents`·`.claude/skills`·`.claude/rules` | 12인 에이전트·스킬·규칙 |
| **공유 — 지식** | `PROJECT/_team/지식/` | 산출물 스킬 마스터 인덱스, MCP 구상 제안서 |
| **공유 — 도구** | `DELIVERABLES/_generators/` | 과제 무관 엔진(`gen_office.py` 엔진부·`gen_docs_from_md.py`) + `projects/<slug>.sh` 러너 |
| **공유 — 캘린더** | Google Calendar "컨버전스1팀 산출물 회의" | 모든 활성 과제 점검(특정 과제 아님) |
| **과제별 — 스펙** | `PROJECT/<slug>/...` (권장) | 단계별 산출물 스펙(SSOT, md) |
| **과제별 — 배포** | `DELIVERABLES/<slug>/<업무>/` | PPTX/DOCX/XLSX/HTML 등 배포본 |

> 현재 상태: **과제 #1 = `IBK_i-ONE_Global`**. 배포본은 이미 `DELIVERABLES/IBK_i-ONE_Global/`로
> 네임스페이스됨. 스펙은 과거 단일 과제 가정으로 `PROJECT/`에 flat(00-sales…05-dev-prep)로 존재 →
> 원하면 `PROJECT/IBK_i-ONE_Global/`로 이전 가능(아래 §4).

## 2. 새 과제 추가 절차
1. `PROJECT/<slug>/` 생성 후 단계 폴더(00-sales … 05-dev-prep) 사용.
2. `DELIVERABLES/<slug>/<업무>/` 생성, `_index.md` 대장 작성.
3. 오피스 배포본은 `DELIVERABLES/_generators/projects/<slug>.sh` 러너를 복제·수정해 생성
   (엔진은 공유, 경로·제목만 과제별).
4. 워크플로우(분석→기획→디자인→퍼블→개발/마케팅)와 게이트는 동일하게 적용.
5. 주간 회의에서 모든 활성 과제를 함께 점검.

## 3. 명명 규약
- 과제 slug: `영문_kebab_or_underscore` (예: `IBK_i-ONE_Global`).
- 배포 파일: `<SLUG약칭>_<업무>_<문서명>_v<버전>.<확장자>`.

## 4. (선택) IBK 스펙 네임스페이스 이전
`PROJECT/00-sales … 05-dev-prep` + IBK 회의록을 `PROJECT/IBK_i-ONE_Global/`로 `git mv`하고
러너(`projects/IBK_i-ONE_Global.sh`)의 `P` 경로를 갱신하면 완전 일관화. 문서 내 상호참조 경로도
함께 수정 필요(영향 범위 있어 사용자 승인 후 진행 권장).
