# 과제 정의서 — Converge 서비스화 기획/설계 (창수 참여·경력화)

> 목적: con-mgt(실적관리)를 **Converge SaaS로 서비스화하는 "기획/설계안 컨셉"**을 만드는 것을 **정식 과제**로 운영하고,
> 그 과정을 **창수(Troy)의 경력 실적으로 남기며 실제 일부를 직접 수행**하게 한다.
> 상위 산출: `00-strategy/01_패키징-방안.md`, `01-architecture/Phase1…`, `02-planning/Phase2…`.

> ⚠ [가정] 아래 3개는 질문 도구 오류로 **기본값을 가정**했습니다. 한 줄로 바꾸면 즉시 재조정합니다.
> - 방향: **서비스기획/PM** · 참여: **일부 오너십+팀 스캐폴딩** · 수준: **경력 전환/재직(자기주도 가능)**

## 1. 과제 개요

| 항목 | 내용 |
| --- | --- |
| 과제명 | Converge 서비스화 기획/설계 (가칭) |
| 슬러그 | `Converge_Servicing` (과제 #3의 실행 트랙) |
| 배경 | 사내 도구 con-mgt가 검증한 가치를 **여러 회사가 쓰는 제품**으로 전환. 그 **기획/설계안 컨셉**이 이번 과제의 산출물 |
| 목표 | ① 서비스화 컨셉·설계안 완성(경영 설득 가능 수준) ② 창수의 **포트폴리오 등급 산출물** 확보 ③ 실제 참여로 역량 습득 |

**서비스화 컨셉 (한 줄):** *"우리가 쓰던 실적관리를, 남들도 5분 만에 쓰는 제품으로."* — 가치→사용자→여정→화면→기술→GTM을 하나의 **서비스 블루프린트**로 잇는 것이 설계안의 골자.

## 3. R&R — 팀 스캐폴딩 × 창수 오너십 (Pairing 모델)

`handoff.md` 규율을 적용한 3스텝 사이클로 각 창수 산출물을 진행한다.

```
① 팀(에이전트)  →  골격 제공: 템플릿 + 체크리스트 + 근거 링크(_source-package)
② 창수(Troy)   →  핵심 알맹이 작성(자기 판단·조사 포함) — 본인 이름으로 커밋
③ 팀           →  리뷰(정우선 PO·나기획 기획·한도전 품질) → 피드백 → 재작업 → 사인오프
```
- 팀 담당: 정우선(PO, 우선순위·기준), 나기획(화면정의 코칭), 한도전(품질 게이트), 차도안(디자인 방향 시).
- 창수 담당: S4~S6(또는 방향별 치환) 실작성 + 조사 + 발표덱 일부.

## 4. 경력으로 남기는 메커니즘 (Evidence)

포트폴리오·경력 증빙이 되도록 **3종 흔적**을 남긴다.

1. **귀속 커밋:** 창수 산출물은 본인 이름으로 커밋(증빙 = git 히스토리).
   ```bash
   git commit --author="창수(Troy) <troy@example.com>" -m "Feat: 서비스 블루프린트 v1 (창수)"
   # 또는 페어작업 시 트레일러:  Co-authored-by: 창수(Troy) <troy@example.com>
   ```
2. **역량 매핑표(§6):** 산출물 → 증명 역량 → 근거 파일/커밋 3열로 정리 → 이력서·포트폴리오에 그대로 인용.
3. **리뷰 사인오프 + 회고:** 각 산출물에 팀 리뷰 결과(통과/보완)를 기록, 과제 종료 시 **회고·평가서**로 마무리(성장 포인트·다음 목표).

## 7. 창수 첫 착수 슬라이스 (스타터 — 성취 가능·고신호)

**추천 시작점: S6 리서치 가이드** (진입장벽 낮고, S4·S5의 근거가 됨)
- 팀 제공(골격): 인터뷰 목적·대상(본부장·PMO)·섹션(현행 고통·엑셀 한계·지불의사) 템플릿 + 가설 A1~A2(패키징 §10).
- 창수 작성: 질문 10~15개, 가설별 검증 질문, 스크리닝 기준, 기록 양식.
