## V1 — 기획: 화면정의 상세  (파일: `V1_화면정의_온보딩STEP1.md`)

아래 뼈대의 `[작성]`을 채운다. (포맷은 Phase 2 화면정의서와 동일 규율)

```md
### 화면: 온보딩 STEP1 회사·조직 (onboarding.company)
- 목적 / 진입 경로: [작성]
- 입력 필드:
  | 필드 | 필수 | 타입/제약 | settings 매핑 |
  | 회사명 | ✅ | 1~50자 | branding.companyName |
  | 로고 | | 이미지 ≤[작성]MB, png/jpg | branding.logo |
  | 조직단위(리스트) | ✅(1+) | 이름 1~30자·중복불가 | orgUnits[]{id,name,order} |
  | 회계연도 시작월 | | 1~12(기본 1) | accounting.fiscalStartMonth |
- 사용자 액션 → API: [작성] (PUT /api/tenant/settings 부분병합)
- 상태: 로딩 / 빈(조직 0개→[다음] 비활성) / 오류(저장실패→롤백·재시도) / 권한없음(member)
- 예외·정책: [작성] (조직 중복·삭제·로고 용량 초과 등)
- 완료 조건(다음 활성): [작성]
```
**게이트:** 나기획 리뷰 — 빈/오류/예외가 모두 정의됐는가.

## V2 — 디자인: UI 시안  (파일: `V2_시안_온보딩STEP1.html`, Claude Design HTML)

**브리프**
- 좌측 진행 스테퍼(1/5 강조) + 우측 폼. 마법사 톤(집중·간결).
- con-mgt 제품 톤 토큰(참고값, 확정은 차도안): primary·회색계·카드 라운드. 자체완결 CSS(외부 의존 0).
- 반드시 그릴 상태: **기본 · 조직 0개(빈, 다음 비활성) · 검증 오류(중복 이름) · 저장 중(로딩)**.
- 컴포넌트: 회사명 인풋, 로고 업로드 드롭존, 조직단위 추가/삭제/순서 리스트, [이전][저장하고 나가기][다음].

**체크리스트**
- [ ] V1의 필드·상태와 1:1 일치(누락 없음)
- [ ] 빈/오류/로딩 상태를 실제로 그림(행복경로만 X)
- [ ] 라이트/다크 또는 최소 라이트에서 대비 확보
- [ ] 카피가 마법사답게 짧고 행동 유도적

**게이트:** 차도안 리뷰(ui-review) — 디자인 시스템·상태 완비·일관성.

## V3 — 개발: 동작 프로토타입  (파일: `V3_프로토타입_온보딩STEP1.html`, vanilla HTML/JS)

con-mgt가 vanilla JS라 **저장소 없이도 실제와 유사한 프로토타입** 가능. 목표: V2 시안이 실제로 "동작"하게.

**구현 스펙**
- 상태 모델: `settings = { branding:{companyName,logo}, orgUnits:[], accounting:{fiscalStartMonth} }` (in-memory).
- 기능: 회사명 입력 · 조직단위 추가/삭제/순서변경 · 로고 미리보기 · [다음] 클릭 시 검증 후 `localStorage`에 mock 저장.
- **검증 로직(필수 구현):**
  - 회사명 공백/길이(1~50)
  - 조직단위 ≥1 · 이름 중복 차단 · 길이(1~30)
  - 위반 시 인라인 에러 + [다음] 비활성
- 상태 반영: 빈(조직0)·오류·로딩(저장 200ms mock)·성공(다음 단계 자리표시 alert).

**체크리스트**
- [ ] V1 검증 규칙이 코드로 그대로 구현됨
- [ ] V2 시안과 화면이 일치(설계-구현 일치)
- [ ] 빈/오류/로딩 상태가 실제로 전이됨
- [ ] 콘솔 에러 0, 자체완결(외부 CDN 없이 열림)

**게이트:** 한도전 품질 게이트 — 동작·검증·일관성. 통과 시 `경력증빙_템플릿.md` 사인오프.
