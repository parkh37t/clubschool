# 제품 전략 · MVP · 로드맵

> 컨버전스 SaaS(과제 #3) · 팀 워크플로우 산출

# 제품 전략: 프로젝트 인력 운영 대시보드 → 멀티테넌트 SaaS 전환

> 작성: PO(정우선) · 근거: 현재 상태 매핑(기능/데이터 모델) + SaaS 전환 진단(한계/기회)
> 원칙: "더 많이"가 아니라 "가장 먼저 팔 수 있는 가장 작은 것". 범위 확장은 비용을 명시하고 결정한다.

---

## 1. 문제 정의

프로젝트 단위로 사람을 투입해 매출을 내는 조직(에이전시·SI·컨설팅)의 **인력 가동은 대부분 엑셀·수기·감(感)으로 관리된다.** 그 결과 세 가지 손실이 반복된다.

1. **유휴/과투입이 실시간으로 안 보인다.** 누가 벤치(유휴)이고 누가 초과투입인지 월말이 지나서야 안다 → 유휴비용이 그대로 마진을 깎는다.
2. **투입 의사결정이 느리다.** 신규 프로젝트에 누구를 넣을지 결정하는 근거(가동률·맨먼스 여력·단가)가 흩어져 있어 "일단 되는 사람"으로 배정된다.
3. **가동률이 재무와 연결되지 않는다.** 가동률(%)은 있어도 그것이 유휴비용·매출기여로 환산되지 않아 경영진 언어로 보고되지 못한다.

핵심은 **"조직의 인력 가동을 가시화하고, 투입 의사결정을 빠르게"** 하는 것이다. 현재 앱은 이 문제를 한 회사(56명) 단일 브라우저 도구로 이미 풀고 있고, 이 가치를 **여러 회사가 각자의 데이터로** 쓰게 만드는 것이 전환의 본질이다.

## 2. 타깃 ICP (Ideal Customer Profile)

| 축 | 1차 타깃 (초기 집중) | 2차 확장 |
| --- | --- | --- |
| **업종** | 디지털 에이전시, 개발 SI/SM, IT 컨설팅 (프로젝트 인력을 투입해 청구하는 조직) | 건설/엔지니어링, 리서치, 로펌 등 프로젝트·케이스 인력 조직 |
| **조직 규모** | **30~200명** (핵심 스윗스팟 40~120명) | 200~500명(멀티 본부), 20명 이하는 무료/셀프서브 |
| **조직 구조** | 그룹/직능 2~3단계, 본부장+PM+실무자 위계 | 다지사·다본부 계층 |
| **핵심 사용자(페르소나)** | ① 본부장/대표 — 전사 가동·유휴비용 모니터링<br>② 사업관리/PMO — 투입 조정·프로젝트 승인<br>③ 팀 리더/PM — 자기 팀 여력 확인 | HR/재무 — 원가·정산 연동 |
| **구매 트리거** | "엑셀 인력 관리가 한계", "가동률을 경영보고에 넣어야 함", "유휴 인건비가 새고 있음" | 원가 정산 자동화, 채용 규모 산정 |
| **왜 이 규모인가** | 30명 미만은 머릿속으로 관리 가능(페인 약함), 500명↑은 이미 ERP/전사 PSA 보유(교체 저항 큼). 30~200명은 **엑셀은 넘어섰지만 대형 PSA는 과함** = 빈 시장 | — |

**제외(Not our ICP):** 개인 프리랜서, 프로젝트 아닌 상시운영 조직(콜센터 등), 시간당 청구가 없는 내부 IT 부서. 이들은 가동률↔비용 연결의 페인이 약하다.

## 3. 가치 제안 (Value Proposition)

> **"엑셀로 흩어진 우리 회사의 인력 가동·맨먼스·유휴비용을 실시간 한 화면으로 보고, 다음 프로젝트에 누구를 넣을지 근거를 갖고 결정하게 해주는 프로젝트 인력 운영 SaaS."**

### 핵심 차별화 (경쟁 대비 왜 우리인가)

| 차별점 | 내용 | 근거/해자 |
| --- | --- | --- |
| **① 가동률 → 유휴비용(원가) 자동 환산** | 가동률(%)을 단가·근무캘린더와 곱해 **유휴비용·투입비용을 자동 산출**. 경영진 언어(돈)로 바로 보고 | 이미 도메인에 맨먼스↔가동률↔유휴비용 계산 규칙이 코드로 존재. 범용 리소스툴(Float 등)엔 없는 재무 축 |
| **② 맨먼스 기반 한국형 인력 운영 모델** | 1.0=1인월 풀가동, 그룹/직능·본부장 승인 워크플로우 등 **국내 에이전시·SI 실무 언어** 그대로 | 해외 PSA(Kantata/Mavenlink)는 언어·프로세스·가격이 국내 중소 조직에 과함 |
| **③ 승인 워크플로우 내장** | draft→review→approved 프로젝트 투입 승인 상태기계가 **인력 배정 결정과 결합** | 리소스 캘린더만 있는 경쟁 도구와 달리 "투입 의사결정" 자체를 제품화 |
| **④ 30분 온보딩 + AI 배정 추천** | 온보딩 위저드로 당일 시작, AI가 "유휴 인력 → 적합 프로젝트" 배정 후보 제안 | TTV(가치 도달 시간) 단축이 곧 리텐션. 차별화 3번 축의 자동화 |

경쟁 지형 요약: **Float/Runn(리소스 캘린더, 재무 약함)**, **Kantata·Kimble(대형 PSA, 무겁고 비쌈)**, **엑셀(대다수의 현실)**. 우리는 "엑셀보다 가볍게 시작, 대형 PSA의 핵심(가동률·원가·승인)만" 포지션.

## 4. MVP 범위 (포함 / 제외)

> MVP 목표 = **"한 회사가 스스로 가입→조직 세팅→가동률·유휴비용 대시보드를 보기까지"를 도움 없이 완주.** 우선순위는 Impact-Effort로 정렬.

### 포함 (MVP In-Scope)

| # | 범위 | 왜 MVP인가 (Impact) | 근거/기존 자산 |
| --- | --- | --- | --- |
| **M1. 멀티테넌시 (최소)** | 전 엔티티 `tenantId`, 테넌트 간 데이터 격리(단일 DB + Row-Level 스코프), 저장키/쿼리 네임스페이스 분리 | SaaS의 전제. 없으면 판매 불가 | 도메인 타입 20여 종 재사용, `tenantId`만 추가 |
| **M2. 인증 + 최소 RBAC** | 이메일/소셜 로그인, 테넌트 멤버십(User↔Tenant↔Role), 3역할(관리자/편집자/뷰어). `createdBy`/`reviewerId`를 실 신원으로 | 데이터 격리·승인·과금의 기반 | 현재 `'current-user'` 리터럴 위조 → 실 신원 주입 |
| **M3. 온보딩 위저드 (최소)** | 조직/그룹 정의 → 멤버·직무·단가 등록(수동+CSV 임포트) → 근무캘린더(근무일/시간)·목표 가동률 설정 | **TTV의 핵심.** 빈 상태에서 첫 대시보드까지 | 기존 mock 하드코딩을 테넌트 설정 엔티티로 승격 |
| **M4. 대시보드 + 가동률/유휴비용** | KPI 요약(총원·활성 프로젝트·평균 가동률·유휴), 그룹별 집계, 유휴비용 원가 환산 | **핵심 가치(Aha)** = 첫 로그인에 가동률·새는 돈이 보임 | `Dashboard`/`Analytics`/차트/집계 로직 재사용 |
| **M5. 인력·프로젝트·투입 CRUD** | 멤버·프로젝트·allocation 관리, 투입 시 맨먼스 재계산, 승인 워크플로우(draft→review→approved) | 대시보드를 채우는 실데이터 입력 경로 | `useDataStore` CRUD 시그니처 유지, 내부만 API로 교체 |
| **M6. AI (최소 1개)** | **"유휴 인력 → 적합 프로젝트 배정 추천"** 1종. 가동률 여력·그룹·단가 기반 후보 3안 제시(사람이 최종 결정) | 차별화 데모 포인트, 온보딩 직후 "다음 액션" 제공 | 기존 `OptimizationRecommendation` 타입을 실데이터 집계로 대체 |
| **M0. 정합성 버그 선(先)수정** | 파생 계산 함수의 모듈 상수(`mockMembers`/`mockMemberManmonths`) 직접 참조 → 인자 주입으로 전환 | **실데이터 이전의 전제조건.** 안 고치면 편집해도 가동률·비용이 목데이터로 고정 | `data/mockData.ts`, `useDataStore.ts:106-116` |

### 제외 (MVP Out-of-Scope, v1+로 연기)

| 제외 항목 | 연기 근거 (비용 vs 가치) |
| --- | --- |
| 결제/구독/요금제 자동화(Stripe 등) | MVP는 수동 인보이스/파일럿 무료. 결제는 PMF 확인 후 |
| 화이트라벨/테넌트 브랜딩 | UI 재사용은 되지만 판매 근거 아님. v2 엔터프라이즈 |
| 다본부·다지사 계층(3단계+ 조직) | 초기 ICP는 2~3단계로 충분. 계층 가변화는 복잡도 큼 |
| SSO/SAML, 감사 로그 심화 | 엔터프라이즈 요구. 30~200명 초기엔 과함 → v2 |
| 실데이터 대량 마이그레이션 도구 | CSV 임포트로 대체. 자동 이관은 수요 확인 후 |
| 서버 사전집계(materialized)·대규모 성능 최적화 | 초기 테넌트 규모(수백 명)는 온디맨드 집계로 충분. v1 |
| 모바일 전용 앱 | 반응형 웹으로 커버. 네이티브는 미정 |
| 다통화/다국어 | 초기 국내(원화·한국어) 고정. 국제화는 v2 |
| AI 2종+ (수요예측·자동 리밸런싱) | MVP는 배정추천 1종으로 가치 검증 후 확장 |

## 5. 성공 지표 (KPI)

> 원칙: MVP는 "가입→가치 도달→유지"의 퍼널 지표에 집중. 재무지표(ARPA)는 v1부터 본격 추적.

| 지표 | 정의 | MVP 목표(파일럿) | v1 목표 | 왜 이 지표인가 |
| --- | --- | --- | --- | --- |
| **활성 테넌트 수** | 최근 7일 내 2명 이상 로그인 + 데이터 편집이 있는 테넌트 | 유료전환 파일럿 **5~10개** | **30개** | SaaS 성장의 기본 카운터. 로고 수 |
| **TTV (Time-to-Value)** | 가입 → 첫 "가동률 대시보드에 실데이터 표시"까지 시간 | **≤ 30분** (온보딩 완주) | ≤ 15분 | 리텐션의 선행지표. 온보딩 이탈 방지 |
| **온보딩 완주율** | 위저드 4단계(조직→멤버→캘린더→목표) 전부 완료 비율 | ≥ 60% | ≥ 75% | TTV의 병목 진단 |
| **주간 활성 유지(WAU 리텐션)** | 가입 후 4주차에도 주1회+ 사용하는 테넌트 비율 | ≥ 40% | ≥ 55% | 진짜 습관화(월말만 쓰면 이탈 위험) |
| **테넌트 로고 리텐션(월)** | 유료 테넌트의 월간 유지율 | 측정만 | ≥ 95%/월 | 매출 지속성. 이탈률(<5%) 관리 |
| **ARPA** | 활성 테넌트당 월평균 매출 (좌석수×단가 모델 가정) | 파일럿=0(무료) | 검증 후 설정(예: 30~80만원/월) | 유닛이코노믹스. v1에 가격 실험 |
| **AI 추천 채택률** | 제시된 배정 추천 후보가 실제 allocation으로 반영된 비율 | ≥ 20% | ≥ 35% | 차별화 기능의 실효성 |
| **가동률 가시성(가치 증명 지표)** | 테넌트 내 "유휴로 식별된 인력/비용"이 대시보드에 노출된 규모 | 정성 인터뷰로 확인 | 케이스화 | 판매·리텐션 근거(ROI 스토리) |

**북극성 지표(NSM) 후보:** "주간 활성 테넌트 수" — 여러 사람이 매주 인력 결정을 이 도구로 내리고 있다는 것이 제품 가치의 압축 신호.

## 6. 단계 로드맵 (분기 단위)

> 전제: 현재(2026 Q3) 단일 브라우저 앱. 의존성 순서 = **정합성 버그 수정 → 테넌시/인증 → API/DB → 온보딩/대시보드 → AI**.
> `.claude/rules/backend.md`의 "`useDataStore` 시그니처 유지 + 내부만 API 교체" 전략 덕에 화면 코드 변경을 최소화하며 진행 가능.

### MVP — 2026 Q3~Q4 (약 2개 분기)
**목표:** 파일럿 5~10개 테넌트가 셀프 온보딩으로 가동률·유휴비용 대시보드를 사용.

- **Q3:** M0(정합성 버그 수정) → M1(테넌시 모델·`tenantId`) → 백엔드+PostgreSQL 구축, `useDataStore` 내부를 API 클라이언트로 교체 → M2(인증+최소 RBAC).
- **Q4:** M3(온보딩 위저드) → M4(대시보드·유휴비용, 파생계산 서버 이전) → M5(CRUD·승인 워크플로우) → M6(AI 배정추천 1종) → **파일럿 온보딩·인터뷰**.
- **의존성:** M0는 모든 것의 선행조건(실데이터 정확성). M4의 서버 계산 이전은 M1(테넌트 스코프) 이후. AI(M6)는 M4/M5 실데이터가 있어야 의미.
- **게이트:** `type-check`/`lint(--max-warnings 0)`/`build` 통과 + 테넌트 데이터 격리 검증.

### v1 — 2027 Q1~Q2 (상용화)
**목표:** 유료 전환·30개 테넌트. 유닛이코노믹스 검증.

- **Q1:** 결제/구독(요금제·좌석 과금), 온보딩 개선(TTV 15분), 서버 사전집계/성능(수백 명 테넌트 대응), 알림(유휴/과투입 임계 경고).
- **Q2:** AI 2종째(**월별 가동률 예측·번다운**), 리포트 내보내기(경영보고용 PDF/월마감), 기간(period) 모델 정식화(YYYY-MM 기준월·월 마감 lock).
- **의존성:** 결제 전 리텐션(4주 40%)·TTV 목표 선(先)달성. 예측 AI는 기간 모델 위에서.

### v2 — 2027 Q3~Q4 (스케일·엔터프라이즈)
**목표:** 200~500명·다본부 조직 진입, 확장 축.

- **Q3:** 다본부·다지사 계층(조직 가변 깊이), 화이트라벨/브랜딩, SSO/SAML·감사 로그.
- **Q4:** 원가/정산 연동(회계·급여 시스템 API), AI 3종(**자동 리밸런싱 제안**), 다통화/국제화, 오픈 API·웹훅.
- **의존성:** 계층 가변화는 초기 2단계 스키마의 리팩터 비용 큼 → v1 데이터 위에서 신중히.

### PO 판단이 필요한 미해결 결정 (가정 금지 — 사용자/경영 결정)
1. **테넌트 격리 방식:** 단일 DB+RLS(운영 단순, 비용↓) vs 스키마/DB 분리(격리 강함, 엔터프라이즈 요구). → MVP는 **단일 DB+RLS 권고**, 대형 고객 시 v2 재검토.
2. **요금 모델:** 좌석당 과금 vs 테넌트 정액 vs 관리 인원수 구간제. → 파일럿 인터뷰로 결정.
3. **조직 계층 깊이:** 초기 2~3단계 고정(권고) vs 처음부터 가변. → 가변은 v2로 연기 권고.
4. **기존 localStorage 사용자 이관:** 현 단일 회사 데이터를 첫 테넌트로 마이그레이션할지. → CSV 임포트로 흡수 권고(전용 이관도구는 수요 확인 후).
