# 온보딩 셋업 마법사 설계 — "기준 데이터만 넣으면 즉시 관리 시작"

작성: PO/서비스기획 · 기준: 현행 `types/index.ts`, `useDataStore`, `VIEW_NAMES`(2026-07-07 소스 기준)
전제: 본 문서는 SaaS 전환(테넌시·백엔드 도입)을 가정한 설계이나, **현행 localStorage 단일 테넌트에서도 그대로 구현 가능한 단계별 폴백**을 병기한다.

## 0. 설계 원칙 (핵심 셀링포인트 = Time-to-Value)

이 제품의 약속은 **"빈 화면에서 시작해 10분 안에 우리 조직의 가동률·유휴비용 숫자를 본다"**이다. 온보딩 전체를 이 한 문장에 종속시킨다.

| 원칙 | 구현 규칙 |
| --- | --- |
| **가치까지 최단 경로** | 마법사 필수 단계는 4개(회사·조직·구성원·기준). 나머지는 전부 "나중에" 스킵 허용. 스킵해도 대시보드가 렌더된다. |
| **기본값이 곧 정답** | 근무일 22일·8h/일·목표 가동률 90% 등을 **선입력된 기본 프리셋**으로 제공. 사용자는 "그대로 확인"만 눌러도 완료. |
| **빈 상태에서도 가치를 보여준다** | 데이터 0건이어도 각 화면은 "이 화면에 무엇이 채워질지"를 샘플 실루엣+CTA로 안내(순수 공백 금지). |
| **되돌릴 수 있게** | 마법사는 언제든 나갔다 재진입(진행률 저장). 시드/샘플 데이터는 1클릭 전체 삭제 가능. |
| **투입 수단 다중화** | 같은 데이터를 템플릿 다운로드·CSV/엑셀 업로드·수기 입력·샘플 복제 4가지 경로로 넣을 수 있게 한다(사용자 상황별 최단 경로 선택). |
| **데이터는 dataStore로만** | 마법사가 만든 모든 데이터도 `useDataStore` CRUD를 통해서만 기록(컴포넌트에서 localStorage 직접 접근 금지, `frontend.md`·`backend.md` 준수). |

**TTV 목표치(측정 KPI):** 회사생성→첫 대시보드 도달 중앙값 ≤ 8분(임포트 경로), ≤ 90초(샘플 경로).

## 1. 기준 데이터 정의 (마스터 스키마)

현행 하드코딩(그룹 5종 리터럴 유니온, 근무일 22·8h·70,000원 상수, 목표 90%)을 **테넌트가 CRUD하는 마스터 데이터로 승격**한다. 아래는 `types/index.ts`에 추가할 신규 타입과 필드다.

### 1-1. 회사/테넌트 — `Tenant`

| 필드 | 타입 | 필수 | 기본값 | 설명/검증 |
| --- | --- | --- | --- | --- |
| `id` | string | O | 서버발급 | 테넌트 식별자(현행 폴백: `generateId('tenant')`) |
| `name` | string | O | — | 회사/본부명. 1~60자 |
| `industry` | string | X | — | 업종(선택 프리셋) |
| `currency` | `'KRW' \| 'USD' \| ...` | O | `'KRW'` | 통화(현행 "원" 고정 → 외부화) |
| `locale` | string | O | `'ko-KR'` | 로케일 |
| `timezone` | string | O | `'Asia/Seoul'` | 타임존(월 마감 기준) |

## 2. 셋업 마법사 — 단계별 UX

라우팅: `VIEW_NAMES`에 아래 뷰 추가 → `ViewRenderer` 분기 → 신규 테넌트/빈 데이터 감지 시 `App` 진입 시 `ONBOARDING`으로 자동 리다이렉트.

```
constants/views.ts 추가:
  ONBOARDING: 'onboarding'          // 마법사 셸(스텝퍼)
  SETTINGS_MASTER: 'settings-master' // 온보딩 후 기준데이터 상시 편집 진입점
  DATA_IMPORT: 'data-import'          // 임포트 재사용(멤버 관리에서도 진입)
```

마법사는 **단일 뷰(ONBOARDING) 안의 내부 스텝 상태**로 구현(라우터 부재 컨벤션 유지). 각 스텝은 헤더 진행률 바 + 좌측 스텝 목록 + 우측 폼 + 하단 [이전/스킵/다음].

### 2-1. 전체 단계 표

| # | 단계 | 화면/모듈 | 목적 | 핵심 입력 | 저장(dataStore CRUD) | 스킵 | 완료 판정 | TTV 기여 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 0 | **시작·모드 선택** | Onboarding: Welcome | 투입 경로 결정 | 회사명, 모드(임포트/수기/샘플/데모) | `createTenant()` | X(필수) | 테넌트 생성 | 샘플/데모=즉시 대시보드로 점프 |
| 1 | **회사 생성** | Onboarding: Company | 테넌트 기본 정보 | 회사명·통화·타임존·회계연도 시작월·로고 | `updateTenant()`,`upsertFiscalSettings()` | 로고만 스킵 | 필수 필드 유효 | — |
| 2 | **그룹/조직** | Onboarding: Org | 조직도·직군 정의 | 그룹(라벨/색), 본부·팀 트리, 조직장 | `seedGroups()`,`upsertOrgUnit()` | O(기본 5그룹 시드로 진행) | 그룹 ≥1 | 기본값 그대로 "확인"만으로 통과 |
| 3 | **구성원 임포트** | Onboarding: Members (+ DATA_IMPORT) | 인력 등록 | CSV/엑셀 업로드 또는 수기 표 입력 | `bulkAddMembers()`(내부 `addMember` 반복) | X(최소 1명) | 유효 구성원 ≥1 | **최대 병목** → 템플릿·검증으로 단축 |
| 4 | **요율/기준** | Onboarding: Rates | 비용·목표·근무 파라미터 | 직무별 요율표, 근무일/시간, 목표 가동률, 프로젝트 카테고리 | `upsertRateCard()`,`upsertCalcParams()`,`seedCategories()` | O(기본 프리셋으로 진행) | 계산 파라미터 유효 | 기본 프리셋 = 무입력 통과 |
| 5 | **완료·검증** | Onboarding: Review | 요약·정합성 최종 확인 | (읽기) 요약 카드 + 경고 목록 | `finalizeOnboarding()` | X | 오류 0 | "지금 대시보드 보기" CTA |
| → | **첫 대시보드** | DASHBOARD | 가치 확인 | — | (읽기) `dashboardStats`,`utilizationData` | — | `firstValueSeenAt` 기록 | 온보딩 성공 지점 |

### 2-2. 화면 정의서 (스킬 포맷 준수)

#### 화면: 온보딩 시작·모드 선택 (view: `onboarding`, step 0)
- **목적/진입:** 신규 테넌트 첫 진입, 또는 빈 데이터 감지 자동 리다이렉트. 회사명 입력 + 4개 모드 카드.
- **표시 데이터:** 없음(생성 화면). 4개 모드 카드(임포트/수기/샘플 테넌트/데모).
- **사용자 액션:** 회사명 입력 → 모드 선택 → `createTenant()` 후 분기.
  - 임포트/수기 → step1로. **샘플 테넌트** → 시드 데이터 주입 후 step5 요약. **데모** → 읽기전용 데모 대시보드로 직행(2-4 참조).
- **상태:** 로딩=버튼 스피너 / 오류=회사명 중복·빈값 인라인 / 권한=온보딩은 테넌트 생성 권한자만.
- **예외·정책:** 회사명 1~60자 필수. 데모 모드는 어떤 저장도 하지 않음(휘발).
- **신규 타입:** `Tenant`, `OnboardingStatus`.

#### 화면: 회사 생성 (step 1)
- **목적/진입:** 모드 선택 후. 테넌트 상세 + 회계 기준.
- **표시 데이터:** `tenant`(방금 생성). 통화/타임존/회계연도 시작월 셀렉트(기본 KRW/Asia-Seoul/1월).
- **사용자 액션:** `updateTenant()`, `upsertFiscalSettings()`.
- **상태:** 빈=기본 프리셋 선입력 / 오류=회계연도 범위 검증.
- **정책:** `currentPeriod`는 온보딩 당월 자동 세팅(사용자 변경 가능).
- **신규 타입:** `FiscalSettings`.

#### 화면: 그룹/조직 (step 2)
- **목적/진입:** 조직도·직군을 정의. 기본 5그룹이 이미 시드되어 표시됨(라벨만 고치면 됨).
- **표시 데이터:** `groups`(시드), `orgUnits`(트리). 그룹 라벨/색 편집 인라인.
- **사용자 액션:** 그룹 라벨 수정·추가·비활성(`seedGroups`/`updateGroup`), 본부·팀 추가(`upsertOrgUnit`), 조직장 지정.
- **상태:** 빈=기본 5그룹 + "우리 회사 조직도로 바꾸세요" 안내 / 오류=형제 노드 내 이름 중복, 순환 부모.
- **정책:** 그룹 최소 1개. 색상은 `chart-1~5` 토큰만(임의 hex 금지). 소속원 있는 그룹 삭제 차단.
- **신규 타입:** `Group`, `OrgUnit`.

#### 화면: 구성원 임포트 (step 3, view 재사용: `data-import`)
- **목적/진입:** 인력 대량 등록. 3-way: [템플릿 다운로드]→[파일 업로드]→[검증·매핑]→[확정], 또는 [수기 표 입력].
- **표시 데이터:** 업로드 후 **미리보기 그리드**(행별 상태: 정상/경고/오류), 컬럼 매핑 UI, 검증 리포트.
- **사용자 액션:** 파일 파싱 → `validateImport()`(순수함수) → 사용자가 오류 수정/중복 처리 결정 → `bulkAddMembers()`(내부적으로 `addMember` 반복 + 정합성 유지).
- **상태:** 
  - 로딩=파싱 진행바 / 
  - 빈=템플릿 다운로드 CTA + "엑셀 없으면 수기로 3명만 넣어보세요" / 
  - 오류=행 단위 오류 하이라이트, 파일 전체 실패 시 원본 그대로 반환 / 
  - 부분성공=정상 행만 커밋 여부 선택.
- **예외·정책:** 3장 검증 규칙 전체 적용. 최소 1명 확정해야 다음.
- **신규 타입:** `ImportJob`, `ImportRowResult`, `ImportError`(3-1 참조).

#### 화면: 요율/기준 (step 4)
- **목적/진입:** 비용·목표·근무 파라미터. 전부 기본 프리셋 선입력 → "확인"만으로 통과 가능.
- **표시 데이터:** step3에서 감지된 **직무 목록**에 요율 입력 그리드, 근무일/시간/목표 가동률 필드, 프로젝트 카테고리 시드.
- **사용자 액션:** `upsertRateCard()`(직무별), `upsertCalcParams()`, `seedCategories()`.
- **상태:** 빈=기본값(22/8/90%/70,000) 표시 / 경고=요율 미입력 직무는 기본단가 상속 배지.
- **정책:** 요율 > 0, 근무일 1~31, 목표 0~100. 미입력 직무는 `defaultHourlyRate` 폴백(집계 붕괴 방지).
- **신규 타입:** `JobRole`, `RateCard`, `ProjectCategory`, `CalculationParams`.

#### 화면: 완료·검증 (step 5)
- **목적/진입:** 최종 요약 + 정합성 경고. "이대로 시작" 게이트.
- **표시 데이터:** 요약 카드(구성원 N명·그룹 M개·평균요율·기준월), **경고 리스트**(예: 요율 없는 직무 3건, 조직 미배정 5명, 퇴사 상태 2명).
- **사용자 액션:** 경고 항목별 [지금 수정](해당 스텝 딥링크) / [무시하고 진행]. `finalizeOnboarding()` → `onboardingStatus='completed'` → DASHBOARD.
- **상태:** 오류(치명적: 구성원 0명·그룹 0개)=진행 차단 / 경고(비치명)=진행 허용.
- **정책:** 치명 오류 0건이어야 완료. 스킵된 단계는 대시보드 상단 "설정 보완" 배너로 이월.

## 3. 데이터 투입 수단 & 검증/중복 처리

요구된 4개 수단을 **동일 검증 파이프라인**에 수렴시킨다(수단만 다르고 검증은 하나).

### 3-1. 수단별 비교

| 수단 | 대상 사용자 | 산출 | 장점 | TTV |
| --- | --- | --- | --- | --- |
| **템플릿(엑셀/CSV) 다운로드** | 인사 데이터가 스프레드시트에 있는 조직 | 표준 컬럼·예시행·드롭다운(그룹/직무 목록 내장) `.xlsx` | 오류 사전 예방(입력 가이드 내장) | 중 |
| **CSV/엑셀 업로드 + 검증** | 위 + 기존 HR 시스템 export | 매핑·검증·부분커밋 | 대량 한 번에 | 중(오류 수정 시간 변수) |
| **시드/샘플 테넌트 복제** | 평가·PoC·"일단 보고 싶다" | 가상 56명·프로젝트 3건 완성 상태 | 90초 내 가치 확인, 이후 실데이터로 교체 | **최상** |
| **수기 입력** | 소규모(≤10명)·엑셀 없음 | 인라인 표 add-row | 진입장벽 0, 즉시 시작 | 상(소규모) |

### 3-2. CSV/엑셀 임포트 파이프라인

```
파일선택 → 파싱(SheetJS) → 컬럼 자동매핑(헤더 유사도) → 사용자 매핑 확정
        → 행별 검증(validateImportRows, 순수함수) → 중복탐지
        → 미리보기 그리드(정상/경고/오류 + 수정 인라인) → 부분/전체 커밋 선택
        → bulkAddMembers (dataStore CRUD, 정합성 유지)
```

**구성원 임포트 표준 컬럼 (템플릿):**

| 컬럼 | 필수 | 매칭 필드 | 검증 |
| --- | --- | --- | --- |
| 이름 | O | `name` | 1~40자 |
| 이메일 | O | `email` | 이메일 형식 + 중복키 |
| 그룹 | O | `group`(Group.label→id) | 마스터 목록 매칭(없으면 "신규 생성?" 제안) |
| 팀 | X | `orgUnitId`(name→id) | 미매칭 시 경고(무배정 허용) |
| 직무 | O | `role`/`JobRole` | 신규 직무 자동 생성 옵션 |
| 시간당요율 | X | `hourlyRate` | 숫자 > 0, 공란=직무요율 상속 |
| 사번 | X | `externalCode` | 중복 판정 보조키 |
| 고용형태 | X | `employmentType` | enum 매칭, 기본 full_time |
| 상태 | X | `status` | enum, 기본 active |

### 3-3. 검증·에러 등급

| 등급 | 처리 | 예시 |
| --- | --- | --- |
| **오류(Error)** — 커밋 불가 | 해당 행 제외, 인라인 수정 유도 | 이름/이메일 공란, 이메일 형식 오류, 요율 음수, 그룹 매칭 실패(생성 거부 시) |
| **경고(Warning)** — 커밋 가능 | 배지 표시 후 진행 허용 | 팀 미배정, 요율 공란(상속), 퇴사 상태, 요율 없는 직무 |
| **정보(Info)** | 안내만 | 신규 직무/그룹 자동 생성 예정 |

**에러 리포트 원칙:** 파일 전체를 실패시키지 않는다(부분 커밋). 오류 행은 원본값 유지한 채 사유·해결법을 한국어로 명시. 다운로드 가능한 "오류 리포트" 제공.

### 3-4. 중복·기존데이터 클리닝 (기존 회원데이터 관점)

같은 인력이 여러 소스에 흩어져 들어오는 상황을 정면으로 다룬다.

| 중복 유형 | 판정 키(우선순위) | 기본 처리 | 사용자 선택 |
| --- | --- | --- | --- |
| **완전 동일** | 이메일 일치 + 이름 일치 | 스킵(무시) | 스킵/덮어쓰기 |
| **동일인 추정** | 이메일 일치, 다른 필드 상이 | **병합 제안**(diff 미리보기) | 병합/신규생성/스킵 |
| **사번 기준 동일** | `externalCode` 일치 | 병합 제안 | 병합/신규 |
| **이름만 동일(동명이인)** | 이름 일치, 이메일 상이 | 별도 생성(중복 아님) | 필요 시 수동 병합 |

**클리닝 규칙:**
- 정규화: 이메일 소문자·공백 trim, 이름 공백 정리 후 비교(표기 흔들림 흡수).
- 병합 시 **필드별 승자 선택 UI**(신규값/기존값 라디오) + 관련 `allocation`/`manmonth` 참조 무결성 보존(멤버 병합 시 투입 이력 이관, `useDataStore` 정합성 규칙 준수).
- 퇴사자(`status='resigned'`)는 임포트는 허용하되 **가동률·비용 집계에서 자동 제외**(빌러블 모수 오염 방지) — 데이터 클리닝의 핵심.
- 되돌림: 임포트 배치는 `ImportJob` 단위로 기록해 "이 임포트 되돌리기" 1클릭 롤백 제공.
