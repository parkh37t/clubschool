## 0. Executive Summary
"외국인 고객 경험을 **이미 만들어 본** 팀." 우리는 SFR-062(외국인 고객센터)·SFR-063(외국인
전자지갑/전자증명서)을 **동작 프로토타입으로 선구현**해, 1단계 디지털 플랫폼의 외국인 채널
경쟁력을 가장 빠르고 확실하게 입증한다. 핵심 리스크(정부24/유통 연동)는 **인터페이스 추상화 +
mock 선개발 → 규격 확정 시 어댑터 교체** 전략으로 일정 리스크를 흡수한다.

## 1. 제안 개요 / 배경 이해
- 발주 목표: 노후('09년) 인터넷뱅킹 구조 → 디지털 플랫폼 리빌딩(채널 중복 제거·출시 속도·
  확장성), **i-ONE Bank Global 재구축으로 외국인 고객 경쟁력 강화**.
- 우리의 이해: 외국인 채널의 성패는 ①다국어·인증 등 **외국인 특화 UX**, ②**정부24/전자문서
  유통시스템 연동**, ③**플랫폼 표준화**. → ①은 프로토타입으로 해소, ②③은 검증된 접근법 제시.

## 6. 연동 아키텍처 (리스크 핵심)
```
[i-ONE Bank Global 앱]
   └─ 외국인 모듈(전자지갑/고객센터)
        └─ Integration Adapter Layer (인터페이스 추상화)
             ├─ Auth Adapter   → 공동인증서 / IBK인증서  (금융인증서 제외)
             ├─ Cert Adapter   → 정부24 / 전자문서 유통시스템 API  [규격 확정 전 mock]
             └─ Notify/Log     → 거래 로그·이벤트(고지표 트래킹 연계)
```
- 규격 미확정 구간은 **mock 스텁**으로 선개발 → 규격 확정 시 **어댑터만 교체**(앱/화면 영향 0).
- 데이터 계약은 타입 단일 원천으로 관리(증명서/언어 확장은 데이터 구동).
