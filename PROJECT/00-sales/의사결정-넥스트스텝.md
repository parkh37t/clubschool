# 의사결정 메모 — 다음 단계 (영업 판단)

> 작성: 한도전(영업·평가 팀장) · skill: `rfp-analysis`, `proposal-writing`
> 맥락: 협상에 의한 계약(제한경쟁입찰)의 **제안 단계**. 투자 판단 기준 = "수주 확률 기여도".

## 결정
- ③ 개발 게이트 개시: **No-Go (현 시점)** — 수주 전 풀개발은 고비용·저효율, 배점 기여 낮음.
  연동 규격 미확정 상태의 개발은 재작업 리스크(되돌릴 수 없는 비용). **수주 후 즉시 전환.**
- ① 확인필요 항목 확정: **Go (1순위)** — 저비용·고효과, 제안 신뢰도 직결.
- ② 핵심 요건 확장: **조건부 Go (2순위)** — 추가 RFP 이미지 입력 필요, 전건이 아닌 배점 높은
  2~3건만 선별 확장.

## 근거
1. 승부처는 제안서 평가. 보유한 SFR-062/063 동작 프로토타입을 제안 차별화 자산으로 전환하는
   ROI가 가장 높다.
2. 최대 리스크는 가격이 아니라 정부24/유통시스템 **연동 불확실성**. 규격 확정이 선행되어야 함.
3. 개발 직행은 보류이지 폐기가 아님. 수주/우선협상 신호 시 ③ 즉시 가동.

## 즉시 실행(수주 전)
1. 확인필요 5종 확정 요청 [모두 추측]: 지원 언어 목록 · 증명서 확장 범위 · API 규격 ·
   평가 배점 가중치 · 예산 규모.
2. 프로토타입 → 제안서 골격화(proposal-writing): 이해·접근전략·차별점·리스크 대응(연동
   mock→실연동 전환계획).
3. ②는 추가 이미지 확보 시 핵심 2~3건만 동일 워크플로우로 확장.

## 사용자 의사결정 입력 요청
- 확인필요 5종 중 알고 있는 값 / 추가 RFP 이미지 / (없으면) 제안서 초안 작성 진행 여부.
