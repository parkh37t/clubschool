## 1. 공통 규칙

### 1-1. 요청/응답 공통 봉투(Envelope)

**요청 공통 헤더** (HTTP 기준 [추측])

| 필드 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `X-Request-Id` | `string` | Y | 클라이언트 생성 UUID v4. 멱등성 키로 사용 |
| `X-Channel-Id` | `string` | Y | 고정값 `"GLOBAL_APP"` |
| `X-Lang` | `string` | Y | BCP 47 언어 코드 (예: `ko`, `en`, `zh-CN`) |
| `Authorization` | `string` | 조건부 | `Bearer {accessToken}`. 인증 필요 API만 |

**응답 공통 봉투**

```typescript
interface ApiResponse<T> {
  success: boolean;          // true = 정상, false = 오류
  data: T | null;            // 정상 시 결과 데이터
  error: ApiError | null;    // 오류 시 에러 객체
  meta?: ResponseMeta;       // 페이지네이션 등 부가 정보
}

interface ApiError {
  code: string;              // 에러 코드 (§5 에러코드 표 참조)
  message: string;           // 개발자용 메시지 (영문)
  userMessage: string;       // 사용자 노출 메시지 (다국어 키 or 번역 문자열)
  retryable: boolean;        // 재시도 가능 여부
  requestId: string;         // 추적용 요청 ID (X-Request-Id 반환)
}

interface ResponseMeta {
  page?: number;
  pageSize?: number;
  totalCount?: number;
}
```

### 1-2. 타임아웃·재시도·멱등성 정책

| 어댑터 | 연결 타임아웃 | 읽기 타임아웃 | 재시도 횟수 | 재시도 대상 조건 | 멱등성 보장 |
| --- | --- | --- | --- | --- | --- |
| AuthAdapter | 3 s | 10 s | 2회 [추측] | 연결 오류, HTTP 5xx (인증 실패·인증서 오류 제외) | `X-Request-Id` 동일 시 서버 중복 처리 차단 [추측] |
| CertAdapter | 3 s | 15 s [추측] | 2회 [추측] | 연결 오류, HTTP 502·503·504 | 증명서 신청: `X-Request-Id` 동일 요청은 기존 접수번호 반환 [추측] |
| NotifyLogAdapter | 2 s | 5 s | 3회 | 연결 오류, HTTP 5xx | 로그 이벤트: 동일 `eventId` 중복 무시 |

- 재시도 간격: 지수 백오프(초회 1 s, 상한 8 s) [추측].
- 최종 실패 시 `ApiError` 봉투로 호출측에 전달. 앱은 재시도 불가 코드(`retryable: false`)이면 사용자에게 안내 후 중단.
- **멱등성 키(`X-Request-Id`)**: 증명서 신청 등 상태 변경 요청은 클라이언트가 UUID를 생성하여 헤더에 포함. 네트워크 단절 후 재전송 시 동일 키를 재사용하면 서버가 중복 신청을 차단하고 기존 결과를 반환.

#### 4-1-1. `logEvent` — 이벤트 로그

**요청**

```typescript
interface LogEventRequest {
  eventId: string;             // 필수. 클라이언트 생성 UUID (멱등성 키)
  eventType: EventType;        // 필수. 이벤트 유형 코드
  userId?: string;             // 조건부. 인증된 사용자 식별자 (가명처리) [추측]
  sessionId?: string;          // 조건부. 앱 세션 ID
  metadata?: Record<string, string>; // 선택. 이벤트 부가 데이터. PII 미포함 원칙
  occurredAt: string;          // 필수. 이벤트 발생 일시 (ISO 8601, UTC)
}

type EventType =
  | 'AUTH_INITIATED'       // 인증 시작
  | 'AUTH_SUCCESS'         // 인증 성공
  | 'AUTH_FAILED'          // 인증 실패
  | 'WALLET_ISSUED'        // 전자지갑 발급 완료
  | 'CERT_LIST_VIEWED'     // 증명서 목록 조회
  | 'CERT_REQUESTED'       // 증명서 신청
  | 'CERT_DOWNLOAD'        // 증명서 다운로드
  | 'CERT_SUBMITTED'       // 증명서 제출
  | 'CUSTOMER_CENTER_CALL' // 고객센터 직통연결
  | 'LANG_CHANGED';        // 언어 변경
```

**응답**: HTTP 202 Accepted, 빈 data.

#### 4-1-2. `logError` — 오류 로그

## 6. 개인정보 보안 처리 원칙

외국인 모듈은 거소신고·외국인등록·출입국·여권 등 민감 개인정보를 처리하므로 아래 원칙을 인터페이스 계약 레벨에서 강제한다.

### 6-1. 최소수집 원칙

| 필드 | 수집 여부 | 근거 |
| --- | --- | --- |
| 내부 사용자 식별자 (`userId`) | 수집 | 인증·서비스 제공 필수 |
| 인증서 일련번호 (`certSerial`) | 인증 세션 종료 시 즉시 파기 [추측] | 인증 목적 한정 |
| 이름·생년월일 등 원문 개인정보 | 어댑터 응답에 미포함. 화면 표시용 마스킹 값만 반환 | 최소수집·마스킹 처리 |
| 여권번호·외국인등록번호 | 전송 구간에서만 처리, 앱 로컬 저장 금지 [추측] | 개인정보보호법 준수 |

### 6-2. 암호화 및 전송구간 보호

- 모든 API 통신은 TLS 1.2 이상 적용 [추측].
- `userId`, `signedData`, `certSerial` 등 식별·인증 필드는 요청 페이로드 내에서도 추가 암호화 적용 검토 [추측, 기관 규격 확정 시 확정].
- 어댑터 내부에서 외부 기관 API 호출 시 클라이언트 인증서(mTLS) 또는 기관별 인증 방식 적용 [추측].

### 6-3. 마스킹 규칙 (화면 표시용)

| 데이터 종류 | 마스킹 형식 [추측] | 예시 |
| --- | --- | --- |
| 사용자 ID / 이름 | 중간 문자 마스킹 | `홍*동` |
| 외국인등록번호 | 앞 6자리 표시, 뒤 7자리 마스킹 | `901225-*******` |
| 여권번호 | 앞 3자리 표시, 나머지 마스킹 | `M12****` |
| 전화번호 | 중간 4자리 마스킹 | `010-****-5678` |

- 마스킹은 어댑터 응답 레벨에서 적용하여 앱 레이어에 원문이 도달하지 않게 한다 [추측, 기관 규격에 따라 조정].

### 6-4. 로그 내 PII 처리

- `logEvent` / `logError` 요청의 `metadata`, `extra` 필드에 PII(이름·번호·주소 등) 미포함 원칙.
- 로그에 포함 가능한 식별자는 가명처리된 `userId`만 허용.
- 로그 저장소 접근 통제 및 보관 기간은 PIA(개인정보 영향평가) 결과에 따라 확정 [추측].

### 6-5. PIA 고려사항 [추측]

- 외국인 개인정보(외국인등록번호·여권번호) 처리는 개인정보 영향평가(PIA) 대상 가능성 있음.
- 개인정보 처리 목적·보관 기간·파기 절차를 약관 및 개인정보 처리방침에 명시.
- 정부24·전자문서 유통시스템 연동 시 개인정보 제3자 제공 동의 절차 필요 여부 법무 검토 필요 [미확정].

## 7. Mock → 실연동 전환 규칙

### 7-1. 어댑터 교체 원칙
