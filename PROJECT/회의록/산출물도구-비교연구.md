# 산출물 생성 도구 — 비교 연구 (전체 학습)

> 작성: 한도전(진행)·구동민(도구 점검)·차도안(디자인 관점) · 목적: "왜 Adobe Express인가, Claude로 더 잘 안 되나"에 답하고 산출물 정책을 정한다.

## 0. 먼저 바로잡기
발표 덱·브랜드 가이드 HTML은 **Claude가 저작한 "Claude 디자인"** 입니다(create_visual_design / 직접 HTML).
Adobe Express는 그 HTML을 **편집 가능한 PPTX/PDF로 변환만** 한 출구입니다.
→ "Adobe가 디자인했다"가 아니라 **"Claude가 디자인하고, 어떤 그릇(PPTX/PDF/Figma)에 담느냐"의 문제**.

## 1. 핵심 사실 — 디자인 ≠ 파일 포맷
- **Claude의 강점 = 디자인 저작(HTML)과 단일 진실 원천(SSOT).** 여기엔 외부 도구가 불필요.
- **약점 = "그릇"(편집형 PPTX/DOCX/XLSX, 디자인 파일 .fig)은 변환기/전용 도구가 필요.**
- 변환 시 손실: Adobe Express 임포트에서 **Acumin Pro → Source Sans 3 폰트 대체** 발생(외부 변환의 전형적 단점).

## 4. 결론 — 정책 권고: "Claude Design First"
1. **모든 비주얼 디자인은 Claude가 HTML로 저작 = Claude Design(SSOT·1차 산출물).** 폰트·레이아웃 100% 우리 통제.
2. **PDF/이미지 → Claude Design 내보내기 또는 브라우저 인쇄**(외부 변환의 폰트 대체 없음). HTML에 `@media print`/`@page` 추가.
3. **"발표자가 PPT에서 직접 편집"할 PPTX가 필요할 때만 → Adobe Express/Canva**(Claude Design 공유 메뉴의 "Send to Adobe Express"로 연결).
4. **편집형 DOCX/XLSX → Google Docs/Sheets.**
5. **디자인 파일·디자인시스템·다이어그램 → Figma**(대체 불가).
→ Adobe Express는 "필수"가 아니라 **Claude Design의 선택적 출구(편집형 오피스 파일용)**. 평소엔 Claude Design이 더 충실하고 자급자족적이다.

## 5. 제안 조치
- 기존 제안 덱·브랜드 가이드 HTML(=Claude Design)에 **인쇄용 CSS 추가** → 무손실 PDF 생성(Adobe 불필요).
- Adobe Express/Canva는 "편집형 PPTX 필요 시"의 보조 옵션으로만 유지.
- Figma(디자인/다이어그램)·Google(DOCX/XLSX)은 각 영역 전용으로 유지.
