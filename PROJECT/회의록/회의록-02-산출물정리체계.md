# 컨버전스1팀 회의록 #02 — 산출물(배포 파일) 정리 체계

> 일시: 2026-06-21 · 진행: 한도전 · 참석: 12인 전원
> 안건: `.md` 스펙을 **실제 배포 파일(PPTX/DOCX/Figma/Express·Claude design/HTML)**로
>        전환·정리하는 표준 체계 수립 (프로젝트별·업무별 열람 가능하게)

## 1. 합의된 원칙
1. **단일 진실 원천(SSOT) = `PROJECT/*.md` 스펙.** 배포 파일은 여기서 파생한다(스펙 변경 →
   배포본 재생성). 내용 충돌 방지.
2. **배포 파일은 별도 폴더 `DELIVERABLES/`에 프로젝트 > 업무 > 파일** 계층으로 보관.
3. **네이밍 규칙**: `IBK_<업무코드>_<문서명>_v<버전>_<YYYYMMDD>.<확장자>`
   (예: `IBK_01영업_제안발표_v1_20260621.pptx`)
4. 도구는 **용도별 표준 1개**로 고정해 일관성 유지(아래 §3).

## 2. 폴더 체계 (제안)
```
DELIVERABLES/
  IBK_i-ONE_Global/              ← 프로젝트
    00_회의록/                   ← 업무
    01_영업제안/
    02_기획/
    03_디자인/
    04_퍼블리싱/
    05_개발준비/
    _index.md                   ← 산출물 목록·버전·링크 대장
```

## 4. 도구 가용성 (현재 MCP 기준)
- ✅ **HTML**: 직접 저작(프로토타입 완료).
- ✅ **PPTX/PDF/PNG**: Adobe Express(HTML 저작 → Express 문서 → PPTX/PDF 파생) 또는 Canva.
- ✅ **Figma**: Figma MCP로 다이어그램·와이어프레임·디자인시스템·UI·프로토타입 생성.
- ⚠️ **DOCX/XLSX**: 직접 생성기 제한적 → Google Docs/Sheets(Drive) 또는 변환(pandoc) 경로.
  생성 시점에 가용성 확인 후 진행.

## 5. 진행 방식
- 1차로 **임팩트 큰 3종 먼저 생성** 권고: ① 제안 발표 PPTX ② 화면설계+UI Figma ③ 프로토타입(보유).
- 이후 나머지를 업무 순서대로 일괄 생성, `_index.md` 대장에 버전·링크 기록.

## 6. 사용자 결정 필요
- 도구 스택 표준(아래 질문) · 1차 생성 우선순위 · 폴더 체계 채택 여부.
