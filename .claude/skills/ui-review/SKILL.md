# UI 리뷰

UI의 일관성·접근성·반응형·토큰 준수를 점검합니다.

## 체크리스트
### 디자인 토큰 (`.claude/rules/design-system.md`)
- [ ] 색상/간격/폰트가 토큰 클래스 사용? (`bg-primary`, `text-foreground`, `chart-1~5` 등)
- [ ] 하드코딩 색(`#hex`, `text-[...]`)이 없는가? 있으면 사유 주석이 있는가?
- [ ] 클래스 병합에 `cn()`을 사용했는가?
- [ ] `components/ui/`의 기존 컴포넌트를 재사용했는가(중복 신규 제작 X)?

### 일관성
- [ ] 카드/간격/타이포가 기존 화면(Dashboard/Analytics 등)과 일치하는가?
- [ ] 같은 의미의 상태(승인/반려/대기, achieved/warning/critical)가 같은 색인가?

### 접근성
- [ ] 색 대비 충분(WCAG AA), 색만으로 정보 전달하지 않는가?
- [ ] 키보드 포커스/포커스 링, 라벨/역할(aria)이 적절한가?
- [ ] `prefers-reduced-motion` 존중하는가?

### 반응형
- [ ] 모바일(뷰어)/데스크톱(관리) 양쪽에서 레이아웃이 깨지지 않는가?
- [ ] `useIsMobile` 분기가 올바른가? 절대 위치 남용이 없는가?

### 다크 모드
- [ ] 의미 토큰만 사용해 다크 모드에서 색이 깨지지 않는가?

## 출력
발견 사항을 심각도(blocker/major/minor)로 분류하고, 각 항목에 파일 경로:라인과 수정
제안을 답니다. 통과 시 "UI 리뷰 통과"로 명시합니다. 결과는 한국어로 작성합니다.
