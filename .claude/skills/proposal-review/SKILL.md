# 제안서 검수

작성자가 아닌 사람이 제출 직전 초안을 판정합니다. 직접 고치는 일이 아니라 **판정하고, 먼저 고칠 것을 고르는 일**입니다.

## 1. 검토 대상 고정
- 첫 줄에 파일 경로 · 버전 · 제출본/발표본 · 대상 RFP 를 적습니다.
- 함께 읽을 것: 요구·평가 대응표, 장표 구성안·근거표, 앞 단계 산출물.

## 2. 필수 점검 — 하나라도 fail 이면 "제출 준비"로 올리지 않습니다
| 항목 | 기준 |
| --- | --- |
| 고객·사업명 | 모든 쪽의 고객명·사업명·버전이 같고, 다른 고객 이름이 섞이지 않음 |
| 요구 대응 | 대응표의 요구가 모두 본문 장·절과 연결되고, 빠진 요구는 `공백`으로 드러남 |
| 평가 순서 | 목차가 평가 항목·배점 순서를 따르고, 배점 큰 항목에 분량이 실림 |
| 숫자 | 합계·단위·기간·인력·금액이 쪽마다 같고 계산이 맞음(비율·퍼센트는 다시 계산) |
| 근거 | 수치·주장마다 출처나 추정/가정 표시가 있음. 측정하지 않은 효과 수치가 없음 |
| 약속 수준 | 완료·수주·효과를 과장하지 않고, 할 수 없는 일을 약속하지 않음 |
| 기밀 | 실명·내부 영업정보·다른 고객 자료가 허락 없이 들어가지 않음 |
| 자리표시 | TBD·xx·[ ]·"예시" 같은 자리표시가 남지 않음 |
| 제목 | 장표 제목이 결론 문장이고, 제목만 이어 읽어도 주장이 이어짐 |
| 형식 | 렌더했다면 글자 넘침·겹침·깨짐 없음. 렌더하지 않았으면 `not_run` |

결과는 항목마다 `pass / fail / not_run` 중 하나와 근거 위치(쪽·장)를 적습니다. 보지 않은 항목을 pass 로 적지 않습니다.

## 3. 평가 항목별 등급
- 항목은 RFP 평가 기준을 그대로 씁니다. 기준이 없으면: 고객 이해 · 전략 연결 · 근거 · 실행 가능성 · 차별성 · 가독성(도식 포함).
- 항목마다 0~4 등급(0 없음 · 1 약함 · 2 보통 · 3 좋음 · 4 매우 좋음)과 근거 쪽을 적습니다. 가중치는 RFP 배점을 따릅니다.
- 판단할 근거가 없으면 등급을 지어내지 말고 "판단 불가"로 둡니다.

## 4. 먼저 고칠 것
- 평가에 미치는 영향이 큰 순서로 1~3개. 각각 위치 · 문제 · 고칠 방향.

## 결과 형식
```md
# 제안서 검수 — <대상 파일> (<버전>)
## 판정: 제출 준비 | 수정 필요
## 필수 점검 (항목 | pass·fail·not_run | 근거 위치)
## 평가 항목별 등급 (항목 | 배점 | 등급 | 근거)
## 먼저 고칠 것 (1~3)
## 확인하지 못한 것
```

## 원칙
- 작성자를 대신해 본문을 다시 쓰지 않습니다.
- 외부 발송·제출은 검수 결과와 별개로 승인 절차를 거칩니다.
- 결과는 한국어로 작성합니다(영어 요청이면 영어).
