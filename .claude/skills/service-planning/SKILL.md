# 서비스 기획

우선순위가 정해진 기능을 구현 가능한 화면·기능으로 설계합니다.

## 절차
1. **IA/내비게이션**: 화면 구조를 정의합니다. 이 앱은 `VIEW_NAMES` 기반 단일 스위치
   라우팅(`ViewRenderer`)을 사용하므로, 새 화면은 뷰 키 + 진입 경로로 정의합니다.
2. **사용자 플로우**: 시작 → 액션 → 결과를 단계로 그립니다(분기/예외 포함).
3. **화면 정의서**: 화면별로 아래를 명세합니다.
4. **정책/규칙**: 권한, 검증 규칙, 상태 전이(프로젝트 draft→review→...).

## 화면 정의서 포맷
```md
### 화면: <이름> (view: <VIEW_NAMES 키>)
- 목적 / 진입 경로
- 표시 데이터 → dataStore의 어떤 값(members/projects/utilizationData 등)
- 사용자 액션 → 호출할 CRUD/핸들러(addProject/updateAllocation/...)
- 상태: 로딩 / 빈 데이터 / 오류 / 권한 없음
- 예외·정책 (검증, 경계값)
- 필요한 신규 타입/필드 (types/index.ts 추가 항목)
```

## 원칙
- 모든 화면에 빈/오류/로딩 상태를 정의합니다(행복 경로만 X).
- 데이터는 `useDataStore`가 제공할 수 있는 형태로 매핑합니다(불가하면 백엔드와 협의).
- 기존 화면 패턴과 일관성을 유지합니다.
- 결과는 한국어로 작성하고, 다음 단계는 디자인(`ui-review`)으로 인계합니다.
