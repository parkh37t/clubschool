# RFP 분석

RFP를 읽고 의사결정과 제안 작성에 바로 쓸 수 있는 구조로 정리합니다.

## 절차
1. **원문 파악**: RFP·과업지시서 전문을 읽고 발주처의 사업 목표(표면 요구 뒤의 의도)를 찾습니다.
2. **요구 분해**: 기능 / 비기능(성능·보안·접근성·반응형·운영·유지보수) / 관리(보고·산출물·인력 자격)로 나누고 요구마다 id 를 붙입니다.
3. **제약 정리**: 예산, 기간·마일스톤, 기술·환경 제약, 인력·상주 조건, 제출 양식·분량.
4. **평가기준 추출**: 항목·배점·평가 방식(정량/정성·발표 여부). 배점이 없으면 "확인 필요".
5. **요구·평가 대응표**: 요구 id → 평가 항목 → 대응할 제안 장. 대응 근거가 없는 요구는 `공백`.
6. **리스크 식별**: 모호한 요구, 범위 팽창, 일정 압박, 외부 의존, 계약 조건.
7. **수주 판단**: Go/No-Go 를 5축으로 — 적합성 · 승산 · 수익성 · 리스크 · 전략가치. 축마다 근거와 판단(상/중/하).

## 산출물 포맷
```md
# RFP 분석: <사업명>
## 사업 목표
## 요구사항 (id | 구분 | 내용 | 원문 위치)
## 제약 (예산 / 일정 / 기술 / 인력 / 양식)
## 평가 기준 (항목 | 배점 | 방식)
## 요구·평가 대응표 (요구 id | 평가 항목 | 대응할 장 | 근거 | 충족 상태 | 공백)
## 리스크 & 가정
## 수주 판단: Go / No-Go 권고 (5축 표와 근거) — 최종 결정은 사람이 한다
## 발주처 질의 목록
## 다음 단계 권장
```

## 원칙
- RFP에 없는 예산·일정·배점은 지어내지 않고 "확인 필요"로 적습니다.
- 요구는 빠짐없이 옮깁니다. 요약 때문에 요구가 사라지면 제안 단계에서 감점됩니다.
- Go/No-Go 는 권고까지만 합니다. 결정은 승인 절차를 거칩니다.
- 결과는 한국어로 작성합니다(영어 요청이면 영어).
