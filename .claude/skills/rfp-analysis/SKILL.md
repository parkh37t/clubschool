# RFP 분석

RFP/요구사항을 분석해 의사결정 가능한 구조로 정리합니다.

## 절차
1. **원문 파악**: RFP/요구사항 전문을 읽고 발주처의 비즈니스 목표(표면 요구 뒤의 의도)를 찾습니다.
2. **요구 분해**: 기능/비기능 요구로 나눕니다.
   - 기능: 화면·기능 목록(이 앱이라면 대시보드/분석/구성원/프로젝트 워크플로우 매핑).
   - 비기능: 성능·보안·접근성·반응형·배포·유지보수.
3. **제약 정리**: 예산, 기간/마일스톤, 기술 제약, 인력 제약.
4. **평가기준 추출**: 발주처가 무엇으로 채점하는지(가격/기술/레퍼런스/일정).
5. **리스크 식별**: 모호한 요구, 범위 팽창 위험, 일정 압박, 의존성.
6. **수주 판단**: Go/No-Go를 적합도·수익성·경쟁·리소스 가용성 근거로 제시.

## 산출물 포맷
```md
# RFP 분석: <프로젝트명>
## 비즈니스 목표
## 핵심 요구 (기능 / 비기능)
## 제약 (예산 / 일정 / 기술)
## 평가 기준 (가중치 추정)
## 리스크 & 가정
## 수주 판단: Go / No-Go (근거)
## 다음 단계 권장
```

## 원칙
- 모호한 항목은 "확인 필요"로 명시하고 임의 가정하지 않습니다.
- 이 제품의 실제 도메인(가동률/맨먼스/투입 관리)에 매핑해 적합도를 평가합니다.
- 결과는 한국어로 작성합니다.
