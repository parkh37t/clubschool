# 규칙: 에이전트 간 인수인계 (Handoff)

여러 에이전트가 한 작업을 이어받을 때 컨텍스트 손실을 막기 위한 규칙입니다.

## 핸드오프 트리거
다음 상황에서 다음 단계 에이전트로 인계합니다.
- 영업(수주 확정) → PO/기획: RFP 분석·제안서가 승인됨
- 기획(화면 정의 완료) → 디자인: IA/플로우/화면정의서 확정
- 디자인(시안 확정) → 퍼블리싱/프론트엔드: 디자인 시스템·시안 확정
- 개발(기능 완료) → 데이터 분석/마케팅: 릴리즈 가능 상태

## 핸드오프 문서 포맷
인계 시 다음을 명시적으로 정리해 다음 에이전트에게 전달합니다.

```md
## 핸드오프: <이전 단계> → <다음 단계>
- 완료한 것: (구체적 산출물과 위치 — 파일 경로/문서)
- 결정 사항: (확정된 의사결정과 근거)
- 미해결/리스크: (다음 단계에서 풀어야 할 것)
- 다음 단계 권장 작업: (우선순위 있는 액션)
- 영향받는 파일/타입: (예: types/index.ts, ViewRenderer.tsx)
```

## 원칙
1. **단일 진실 원천**: 도메인 타입은 `types/index.ts`, 데이터 흐름은 `useDataStore`.
   인계할 때 이 두 곳에 미친 변경을 반드시 적시합니다.
2. **추측 금지**: 결정되지 않은 사항은 "미해결"로 명시하고 임의로 가정하지 않습니다.
   판단이 필요하면 사용자(또는 PO 에이전트)에게 질문합니다.
3. **추적 가능성**: 산출물은 항상 파일 경로/커밋으로 가리킬 수 있어야 합니다.
4. **되돌림 가능성**: 큰 구조 변경 전에는 영향 범위를 핸드오프 문서에 먼저 기록합니다.
5. **언어**: 핸드오프 문서는 한국어로 작성합니다.
