# 규칙: 품질 체크 (머지 전 게이트)

코드를 머지/푸시하기 전에 아래 게이트를 모두 통과해야 합니다.

## 필수 자동 검사
```bash
npm run type-check   # 타입 오류 0
npm run lint         # 경고 포함 0 (--max-warnings 0)
npm run build        # 프로덕션 빌드 성공
```
- 하나라도 실패하면 머지 금지. 실패 출력을 그대로 보고합니다(숨기지 않음).

## 코드 리뷰 체크리스트
- [ ] 도메인 데이터 변경이 `useDataStore`를 통하는가? (localStorage 직접 접근 없음)
- [ ] 새 타입/필드가 `types/index.ts`에 정의되었는가?
- [ ] 새 화면이 `VIEW_NAMES` → `ViewRenderer` → 네비게이션까지 연결되었는가?
- [ ] 색상/간격/폰트가 디자인 토큰을 사용하는가? (`design-system.md`)
- [ ] `any` 사용이 없는가? (불가피 시 사유 주석)
- [ ] 연관 데이터 정합성(allocation/manmonth 재계산)이 유지되는가?
- [ ] 맨먼스(0~1)·가동률(0~100) 범위 clamp가 지켜지는가?
- [ ] 다크 모드에서 색이 깨지지 않는가?
- [ ] 모바일/데스크톱 양쪽에서 레이아웃이 동작하는가?

## 보고 원칙
- 테스트/검사를 건너뛰었다면 "건너뜀"이라고 명시합니다.
- 완료·검증되었다면 군더더기 없이 "통과"로 분명히 보고합니다.
- 회귀 위험이 있는 변경은 영향 범위를 함께 적습니다.

## 되돌릴 수 없는 작업
- 데이터 초기화/대량 삭제/외부 배포 등은 실행 전 확인을 받습니다.
